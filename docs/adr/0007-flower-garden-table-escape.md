# Flower-garden table escape: two-leg exit flight through the matched rose

The flower-garden table exercise needed a match-success payoff for the captured roamer, the role the undersea theme fills with a bubble pop followed by the koi swimming straight off-screen. We chose a two-leg **exit flight** — the roamer leaves the orb at its center, flies through the matched rose's position as a waypoint (constant speed, no landing), then continues to an off-screen point beyond the screen edge nearest that rose and is permanently eliminated. This diverges from the undersea model (which exits straight to a deterministic off-screen point) for two reasons: the pass-through keeps the learner's eye on the cell they just matched, and the nearest-edge rule makes the departure path read as a natural continuation of the orb→rose direction instead of a visible bend toward a fixed edge. The waypoint turn happens at constant speed so the motion reads as "flew through", not "landed and took off again".

The capture orb's burst therefore carries an **intent** — `Release` (user taps the orb: petals scatter, roamer returns to cruise flight, as before) vs `Escape` (match success: petals scatter, roamer starts the exit flight). The flower roamer flight state machine gained two terminal-adjacent states: `ESCAPING` (waypoint steering) and `ESCAPED` (frozen; the sim frame loop stops updating it and reports the index so the theme hides it permanently).

**Cross-references:** the exit path is resolved by a theme-local pure function (`resolveRoamerExitPath`) instead of the core's `computeOffScreenEscapeTarget`, because the requirement is nearest-edge-to-rose rather than the deterministic orientation-based edge the core helper provides. The capture-bridge contract (ADR-0003) is unchanged; the orb side now publishes the same `RoamerCaptureBridge` the undersea bubble publishes. New terms in `CONTEXT.md`: `Exit flight`, burst `intent` on the capture orb.
